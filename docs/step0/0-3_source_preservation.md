# 現行プログラム保全

## 1. 目的
現行プログラムをリファクタリング前の基準状態として保存し、以降の変更を安全に追跡・巻き戻しできる状態にする。

## 2. 現状
- GitHubリポジトリで管理済み
- これまでの作業は主に master ブランチで実施
- ブランチ運用は明確に定義されていない

## 3. 保全方針
- master ブランチをリファクタリング前の安定状態として扱う
- リファクタリング前の状態にタグを付与する
- 以降の作業は専用ブランチで行う
- master への直接コミットは原則行わない

## 4. 作成するタグ
- v0.0.0-before-refactoring

## 5. ブランチ運用
| ブランチ | 用途 |
|---|---|
| master | 安定版・保全用 |
| step0/project-setup | STEP.0 作業用 |
| step1/current-code-analysis | STEP.1 現行プログラム整理 |
| step2/requirements | STEP.2-1 要件定義 |
| step2/design | STEP.2-2 基本設計 |
| step2/refactoring | STEP.2-3 実装 |
| step2/test | STEP.2-4 テスト |

## 6. 作業手順
1. Git状態を確認する
2. 未コミット変更を整理する
3. master に最新状態を反映する
4. リファクタリング前タグを作成する
5. STEP.0用ブランチを作成する
6. docs ディレクトリを作成する
7. .gitignore を確認する

## 7. 完了条件
- master が最新状態である
- リファクタリング前タグが作成されている
- STEP.0用ブランチが作成されている
- 今後 master に直接コミットしない運用が決まっている
- docs ディレクトリが作成されている
- .gitignore の確認が完了している
