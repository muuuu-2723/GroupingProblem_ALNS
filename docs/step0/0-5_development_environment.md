# 開発環境・実行環境の整備

## 1. 目的

本項目では、現行プログラムをビルド・実行できる環境を整理し、STEP.1以降でユーザーおよびGitHub Copilotが同じ手順で動作確認できる状態にする。

また、通常実行とデバッグモード実行の違い、依存ライブラリ、文字コード、動作確認基準を明確にする。

---

## 2. 対象プログラム

本プログラムは、`Data/` ディレクトリ配下のJSONファイルを入力として、グループ分け問題をAdaptive Large Neighborhood Search（ALNS）により解くC++プログラムである。

入力された問題定義に基づいて近似解を探索し、評価値、グループ分け結果、実行時間をコマンドライン上に出力する。

## 6. Makefileの概要

本プログラムは、リポジトリ直下の `Makefile` によりビルドする。

Makefileでは、コンパイラとして `g++` を使用する。

```makefile
GCC    = g++
CFLAGS = -O3 -std=c++17 -finput-charset=CP932 -fopenmp
```

Windows環境では、以下のオプションが追加される。

```makefile
CFLAGS += -fexec-charset=CP932
```

### 主なコンパイルオプション

| オプション | 内容 |
|---|---|
| `-O3` | 最適化レベル3 |
| `-std=c++17` | C++17でコンパイル |
| `-finput-charset=CP932` | ソース入力文字コードをCP932として扱う |
| `-fexec-charset=CP932` | Windowsのみ、実行時文字列の文字コードをCP932として扱う |
| `-fopenmp` | OpenMPを有効化 |

---

## 7. OpenMPの扱い

OpenMPは必須ではないが、推奨とする。

本プログラムでは、実行時のボトルネックとなる `for` 文を並列処理するためにOpenMPを使用している。

OpenMPを無効化しても実行自体は可能だが、問題サイズによっては解が出るまでの時間が長くなる可能性がある。

OpenMPを無効化する場合は、Makefileの `CFLAGS` から `-fopenmp` を削除する。

```makefile
CFLAGS = -O3 -std=c++17 -finput-charset=CP932
```

---

## 8. 文字コード

現行ソースコードはCP932を前提としている。

そのため、Makefileでは以下のコンパイルオプションを指定している。

```makefile
-finput-charset=CP932
```

Windows環境では、実行時文字列の文字コードもCP932として扱うため、以下を追加している。

```makefile
-fexec-charset=CP932
```

WSL2環境でも、`-finput-charset=CP932` のままビルド可能であることを確認済みである。

本プロジェクトでは、現時点でソースコードをUTF-8へ変更する予定はない。

### コメント整理時の注意

STEP.1-1でコメントを整備する場合、既存ソースコードの文字コードを勝手にUTF-8へ変換しない。

## 9. ビルド手順

リポジトリ直下で以下を実行する。

```bash
make
```

ビルド時、OSに応じて以下の補助スクリプトが実行される。

| OS | スクリプト |
|---|---|
| Windows | `bat/make_build.bat` |
| Linux / WSL2 | `shell/make_build.sh` |

これらのスクリプトは、`obj/` および `bin/` 配下の必要ディレクトリを作成するために使用される。

---

## 10. 出力される実行ファイル

OSにより、生成される実行ファイル名が異なる。

| OS | 実行ファイル |
|---|---|
| Windows | `bin/run.exe` |
| Linux / WSL2 | `bin/run.out` |

---

## 11. 通常実行手順

### WSL2

以下のコマンドで動作確認済みである。

```bash
./bin/run.out -p Data/A-n32-k5.json
```

### Windows cmd

以下のコマンドで動作確認済みである。

```cmd
bin\run.exe -p Data\A-n32-k5.json
```

問題ファイルには、`Data/` ディレクトリ内の問題ファイル名、または問題ファイルへのパスを指定する。

ただし、ファイル名のみではうまくファイルを見つけられない場合があるため、原則としてパス指定を推奨する。

---

## 12. デバッグモード実行

実行コマンドに `-d` を付与すると、デバッグモードで実行する。

デバッグモードでは、探索中の各種パラメータ推移を `.dat` ファイルとして出力しながら、`matplotlib.hpp` を用いてリアルタイムにグラフ出力を行うことができる。

デバッグモード時には、主に以下のソースコードが関係する。

- `src/Debug/Debug.hpp`
- `src/Debug/Debug.cpp`
- `src/include/matplotlib.hpp`

デバッグモードでは `matplotlib.hpp` が `python` コマンドを呼び出すため、Python実行環境が必要である。

---

## 13. draw_graph.py の位置づけ

`src/DrawGraph/draw_graph.py` は、メインプログラムの通常実行には関係しない。

このスクリプトは、デバッグモードで出力された `.dat` ファイルをもとに、グラフの画像ファイルを出力するための補助スクリプトである。

したがって、通常実行だけを行う場合、`draw_graph.py` およびPython実行環境は必須ではない。

## 15. 実行結果

通常実行が成功すると、コマンドライン上に以下が出力される。

- 評価値
- グループ分け結果
- 実行時間

デバッグモードでは、上記に加えて、各種パラメータ推移の `.dat` ファイルが出力される。

---

## 16. 正常終了の判断基準

実行成功の判断基準は以下とする。

- プログラムが異常終了しない
- コマンドライン上に解が出力される
- 評価値が表示される
- グループ分け結果が表示される
- 実行時間が表示される

正常終了時の終了コードは `0` である。

ただし、現行プログラムでは、C++標準の終了コード以外に独自の終了コード管理は行っていない。

---

## 17. clean手順

ビルド成果物を削除する場合は、以下を実行する。

```bash
make clean
```

`make clean` では、以下が削除対象となる。

- オブジェクトファイル
- 依存関係ファイル
- 実行ファイル

ただし、`obj/` や `bin/` ディレクトリ自体は削除されない。

## 18. STEP.1以降での注意事項

### 18-1. 文字コード

現行ソースコードはCP932前提であるため、Copilotやエディタによる自動変換でUTF-8へ変更しない。

### 18-2. 実行結果の再現性

`Data/A-n32-k5.json` は動作確認用サンプルとして使用できるが、探索には乱数が関係するため、毎回同じ結果になるとは限らない。

そのため、STEP.1時点の動作確認では、完全一致の結果比較ではなく、以下を確認する。

- 実行が完了すること
- 解が出力されること
- 評価値が表示されること
- 実行時間が表示されること

### 18-3. OpenMP

OpenMPは推奨だが必須ではない。  
OpenMPの有無によって実行時間が変わる可能性がある。

### 18-4. デバッグモード

デバッグモードは通常実行とは依存関係が異なる。  
デバッグモード確認時はPython実行環境も確認する。

0-5は、以下を満たした時点で完了とする。

- `make` によりビルドできる。

- 実行後、評価値・グループ分け結果・実行時間が表示される。
- OpenMPが必須ではなく推奨であることが明文化されている。
- デバッグモードではPythonが必要であることが明文化されている。
- `draw_graph.py` が通常実行には不要であることが明文化されている。
- ソースコードの文字コードをCP932のまま扱う方針が明文化されている。
